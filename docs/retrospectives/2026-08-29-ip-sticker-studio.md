## 1. 目标与最终交付

目标是把用户图片转换为个人 IP 表情贴纸，并完成 GitHub 同步、Vercel 部署、`idigits.app` 二级域名绑定，以及火山方舟服务端调用。

已交付：

- 独立 GitHub 仓库 `Ali1995A/ip-sticker-studio`，主分支 `main`。
- Vercel 生产项目与 `sticker.idigits.app` 自定义域名。
- 服务端 Ark API 调用：密钥只保存在 Vercel 环境变量，浏览器不接触密钥。
- 单张 3×4 贴纸整页：一次生成 12 个可裁切表情，而不是发起 12 次请求。
- iPad 横屏及微信内浏览器兼容处理：相册/相机不强制单一路径、图片压缩和旧 API 回退。
- 生成结果可点按放大；最新生成与本机历史合并在同一结果容器中。
- 火山图片同源中转后写入 IndexedDB，目标为同一设备/同一浏览器保留最近 20 张。
- 自定义 favicon。

## 2. 做得好的部分

### 交付路径完整

代码、GitHub、Vercel、Cloudflare DNS、生产域名和 Vercel 环境变量都已接通。部署检查持续使用生产域名确认，而非只看构建输出。

### 按用户真实使用方式调整

页面从普通移动端布局收敛成适合 iPad 横屏的单工作台；上传控件取消 `capture` 强制行为，以便微信内浏览器同时提供相册与相机选择。

### 及时纠正接口契约误判

火山模型对尺寸有两层约束：格式必须是 `WIDTHxHEIGHT` / `2k` / `3k` / `4k`，且本模型实际要求至少 3,686,400 像素。最终采用刚好满足像素下限的 `1920x1920`。

### 安全边界清晰

Ark Key 始终留在 Vercel；基础设施交接文件只记录入口、ID、路径和验证命令，不记录 Token、Cookie、密码或私钥。

## 3. 问题、根因与修正

| 问题 | 根因 | 已采取修正 | 结论 |
| --- | --- | --- | --- |
| 用户看到“deployment error” | 实际是 `POST /api/generate` 的 Vercel Runtime Timeout（60 秒），不是构建失败 | 区分部署状态与函数日志，降低无效重试 | 必须先看 runtime logs |
| `1K` / `1024x1024` 参数错误 | 先只按文档格式理解，未同时满足模型最小像素约束 | 改为 `1920x1920` | 规格必须以模型返回为准 |
| 对“12 张”的理解不一致 | IP 技能默认偏向 12 个资产，用户想要一次得到一张含 12 格的图 | 明确改为单张 3×4 整页 | 用户使用场景优先于默认模板 |
| “本机历史”看似存在但只有最新图 | IndexedDB 写入事务中夹杂读取，且第三方图片 URL 可能不能跨域下载 | 先修复事务顺序，再增加受限同源图片中转 | 仍需真实成功生成连续两次验收 |
| 错误显示 `[object Object]` | 上游错误对象直接转为文本 | 服务端提取 `error.message`、`error.code` 等可读字段 | 错误必须规范化后返回 |

## 4. 未完成验证与风险

### P1：实际生成仍可能超过 Vercel 60 秒

`1920x1920` 满足火山模型尺寸要求，但比先前的 2k 只略小。当前函数仍是同步请求，若上游耗时超过 60 秒，Vercel 会终止请求。若实测仍发生，应停止反复调尺寸，转向以下其中一种架构：

1. 采用火山异步任务接口，由浏览器轮询任务状态；或
2. 将生成后端迁移到允许更长执行时长、且适合异步任务的服务。

### P1：本机历史需要一次真实双次生成验收

已新增 `api/image.js` 同源图片中转，理论上解决跨域下载问题；但本次没有在不必要计费的前提下主动发起真实生图。用户应连续生成两次，刷新页面后确认两张都留在主结果容器中。若失败，查看 Vercel `GET /api/image` 日志中的实际图片主机名和响应大小。

### P2：iPad Pro / 微信内浏览器为代码兼容，尚缺实机验收

已加入 `FileReader` / `Image` 回退和 `dialog` 回退，但需要在目标设备上验证：上传入口、相机/相册选择、图片压缩、生成结果放大、刷新后历史。

### P2：iOS 主屏图标

当前提供 SVG favicon。浏览器标签页可用；若需“添加到主屏幕”也使用专属图标，应另做 PNG `apple-touch-icon`。

## 5. 可复用经验

- 生成式接口必须在小流量实测后再固定尺寸、时限和轮询方式；文档中的“可选值”不代表每个模型都可用。
- Serverless 的构建 Ready 与业务可用是两回事，排障路径应是：域名 HTTP 状态 → 函数错误日志 → 上游模型响应。
- 将远程生成图显示在 `<img>` 中不等于它可被浏览器下载。需要“本机保存”时，应首先检查 CORS 与 IndexedDB 事务边界。
- 对 iPad / 微信容器，上传 input 不应强制 `capture`；同时准备现代 API 和旧设备回退。
- 有效交接文档应包含入口和验证法，而非敏感值本身。

## 6. 当前推荐下一步

1. 以真实参考图连续生成两次；确认 `1920x1920` 可在 60 秒内完成。
2. 刷新页面，确认两张结果仍显示且可放大/下载。

4. 如果任一生图请求再次超时，开始异步任务方案，不再继续微调同步接口。
